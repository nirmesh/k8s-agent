Implement Phase 7: Controlled Remediation Executor.

Add endpoint:

POST /api/remediations/{id}/approve

and/or

POST /api/remediations/{id}/execute

Execution requirements:

1. load stored remediation plan
2. ensure plan status is AWAITING_APPROVAL
3. rerun policy validation
4. verify preview is not stale
5. record approval
6. capture pre-change state
7. execute ONLY the stored approved tool + arguments
8. record Kubernetes response
9. transition to VERIFYING
10. invoke verification
11. update incident state

The browser must never supply a new patch during approval.

Bad:

{
  "approved": true,
  "patch": {...}
}

Good:

{
  "remediationId": "rem-123"
}

The backend executes the immutable previously previewed plan.

Prevent double execution.

Use unique remediation IDs and execution IDs.

Record timestamps for every state transition.

If Kubernetes rejects the operation, mark remediation FAILED and preserve error information.

Do not automatically rollback yet.

Add integration tests.
