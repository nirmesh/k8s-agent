Implement Phase 1: Generic Kubernetes Tool Layer.

Do not modify the UI yet.

Create a reusable Kubernetes tool/service layer.

Required READ operations:

1. get_resources(kind, namespace?)
2. get_resource(kind, namespace, name)
3. get_events(namespace, resource_name?)
4. get_logs(namespace, pod, container?, tail_lines?)
5. get_owner(kind, namespace, name)
6. get_rollout_status(kind, namespace, name)

Required WRITE operations:

7. patch_resource(kind, namespace, name, patch)
8. apply_resource(manifest)
9. restart_workload(kind, namespace, name)
10. rollback_workload(kind, namespace, name)
11. scale_workload(kind, namespace, name, replicas)

IMPORTANT:

Do not expose arbitrary shell execution.

Do not implement:

run_command(command)
execute_shell(command)
kubectl(command)

Use Kubernetes API/client.

Every tool must return structured JSON.

Success example:

{
  "success": true,
  "tool": "get_resource",
  "data": {},
  "error": null
}

Failure example:

{
  "success": false,
  "tool": "get_resource",
  "data": null,
  "error": {
    "code": "NOT_FOUND",
    "message": "..."
  }
}

WRITE operations must support a dry-run or preview mechanism where Kubernetes supports it.

Add unit tests for argument validation and tool behavior.

At completion show:

- files created
- files modified
- tool interface
- how existing backend calls tools
- tests
- commands to run tests

Do not proceed to the agent loop.
