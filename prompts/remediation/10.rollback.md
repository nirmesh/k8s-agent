Implement Phase 9: Rollback.

For every supported mutation determine rollback information BEFORE execution.

For patch_resource:
store sufficient pre-change state to restore changed fields.

For Deployment changes:
prefer Kubernetes rollout revision/history where appropriate, while also retaining audit information about the original configuration.

Add:

POST /api/remediations/{id}/rollback

Rollback itself must:

1. validate target
2. validate policy
3. record action
4. execute rollback
5. verify rollback
6. update remediation state

Do NOT automatically rollback every failed remediation.

For now, when verification fails:

status = FAILED

UI:

Remediation did not resolve the incident.
