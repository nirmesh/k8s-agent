Implement Phase 4: Remediation Policy Engine.

No write operation may reach Kubernetes without passing this layer.

Create deterministic policy validation independent of the LLM.

Input:

RemediationPlan

Output:

{
  "allowed": true,
  "approvalRequired": true,
  "risk": "MEDIUM",
  "violations": [],
  "warnings": []
}

Initial rules:

READ operations:
AUTO ALLOWED

LOW risk:
- rollout restart
- restart stateless workload

MEDIUM:
- change container image
- change replica count
- change resource requests/limits
- change probes
- modify Service selector

HIGH:
- RBAC modifications
- NetworkPolicy changes
- storage configuration
- StatefulSet structural changes
- node operations

CRITICAL / BLOCKED:
- delete namespace
- delete PVC
- delete PV
- delete CRD
- delete node
- modify cluster-admin
- arbitrary shell execution

LOW, MEDIUM and HIGH write operations require human approval for now.

CRITICAL operations are rejected.

Validate:

- namespace exists
- target exists
- target matches diagnosis
- requested operation is registered
- requested patch only changes declared fields
- no unexpected additional mutation exists

Create a configurable policy file so rules are not hardcoded throughout application logic.

Example:

config/remediation-policy.yaml

Never rely on LLM-provided risk classification.

The policy engine calculates risk independently.

Add tests demonstrating blocked dangerous operations.
