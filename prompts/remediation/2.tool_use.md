Implement Phase 2: Tool-Using SRE Investigator.

Keep the existing Ollama + llama3.2 integration.

Do NOT add Hermes, kagent or LangGraph.

Implement a bounded agent loop around Ollama.

Conceptually:

user incident
    |
    v
Ollama
    |
    +-- final diagnosis -> stop
    |
    +-- read tool request
            |
            v
      execute Kubernetes tool
            |
            v
      return observation to Ollama
            |
            +---- repeat

Maximum tool iterations: 10.

The model must be able to request ONLY registered tools.

Initially expose ONLY these read tools:

- get_resources
- get_resource
- get_events
- get_logs
- get_owner
- get_rollout_status

DO NOT expose write tools to the investigation loop yet.

Create a strong system prompt:

"You are a Kubernetes SRE investigator.

Your job is to determine the root cause of Kubernetes incidents using evidence.

Do not assume cluster state.

Use available tools to gather evidence.

Prefer this investigation sequence when applicable:

resource status
-> Kubernetes events
-> owner/workload
-> workload manifest
-> relevant logs

Do not keep calling tools after sufficient evidence exists.

Do not invent resources, logs, events, image tags, namespaces or configuration.

If evidence is insufficient, explicitly state what evidence is missing.

When root cause is established, return a structured diagnosis.

You cannot modify the Kubernetes cluster."

The final result must be structured:

{
  "status": "DIAGNOSED | NEED_MORE_EVIDENCE | UNKNOWN",
  "incidentType": "...",
  "rootCause": "...",
  "explanation": "...",
  "confidence": 0.0,
  "affectedResources": [],
  "evidence": [
    {
      "source": "event|log|resource|manifest",
      "description": "...",
      "value": "..."
    }
  ]
}

Log the agent trace internally:

iteration
LLM request
tool called
arguments
tool result
duration

Do not expose chain-of-thought or hidden reasoning.

It is OK to expose a concise activity trace such as:

Checked Pod
Read Kubernetes events
Found owning Deployment
Inspected Deployment configuration

Add protection against:
- nonexistent tool names
- malformed arguments
- infinite loops
- repeated identical tool calls
- Ollama returning invalid JSON
- tool execution failures

Test using the real Kubernetes cluster where possible.

Do not implement remediation yet.
