Implement Phase 5: Remediation Preview.

Before any Kubernetes write operation:

1. retrieve current resource
2. preserve original state required for rollback/audit
3. validate proposed operation
4. perform Kubernetes server-side dry-run where supported
5. determine resulting resource
6. calculate semantic before/after changes
7. return a preview

API:

POST /api/remediations/preview

Input:
incidentId or remediationPlanId

Return:

{
  "remediationId": "...",
  "status": "AWAITING_APPROVAL",

  "target": {
    "kind": "Deployment",
    "namespace": "default",
    "name": "broken-nginx"
  },

  "risk": "MEDIUM",

  "summary": "...",

  "changes": [
    {
      "path": "spec.template.spec.containers[nginx].image",
      "before": "nginx:this-tag-does-not-exist",
      "after": "nginx:1.29"
    }
  ],

  "verification": {...},

  "rollback": {...}
}

Do not return enormous complete manifests to the UI unless requested.

Provide semantic changes by default.

Do not execute the change.

Store enough state to guarantee that the approved plan cannot silently change between preview and execution.

If cluster state changes between preview and execution, reject stale approval and require a new preview.
